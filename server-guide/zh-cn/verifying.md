# 确认行为已加载

## 启动摘要

一次健康的启动会往控制台打一段简短摘要：一行 *Startup config*（调度器、砧板模式、漏斗设置、进度），以及一行
*Content ready*，数出加载了多少烹饪锅和砧板配方、生物掉落规则、宠物食物和进度。数字对得上，就说明内容解析成功。

想看逐子系统的细分（语言文件、方块行为、tick 管理器、配方数、掉落规则），打开 `startup` / `recipe` / `loot` 调试类别
——见 [故障排查](troubleshooting.md)。正常服务器上不需要它。

## FarmersDelight 对配置写错的方块采取「快速失败」

读控制台时，这是最需要理解的一点。

每个自定义方块都在它的 CraftEngine 配置里声明一个**行为（behavior）**，而一个行为可能需要某个特定的方块**属性
（property）**才能工作。举例：`farmersdelight:rich_soil_farmland` 需要一个湿度属性（由 `moisture-property` 命名的
水位属性，默认是原版的 `moisture`）。湿度驱动整个方块——干涸、复水，以及生长加成。

如果一个方块声明了这样的行为，但它的配置**缺了所需的属性**，FarmersDelight **不会**默默加载一个坏掉的方块。它会
**中止该行为的加载**，并打一条报错，报错里点名：

- **配置节点**（配置写错的那个方块），以及
- 它找不到的**属性名**。

方块本身仍然存在于世界里——只是**失去了那个行为**（否则它就会像一块湿度永远不变的惰性耕地，所以拒绝加载才是诚实的
结果）。

### 怎么读它

> 控制台里的一条 CraftEngine 行为报错是**信号，不是崩溃**。它在明确告诉你：哪个方块的配置写错了、缺了哪个属性。

看到一条时：

1. 记下报错里的方块 id 和属性名。
2. 打开 `plugins/CraftEngine/resources/farmersdelight/configuration/` 下那个方块的定义。
3. 确认所报的属性在该方块上存在（或者 `moisture-property` / 相关的 `*-property` 参数指向了方块确实声明的属性）。
4. 执行 `/ce reload`，确认报错消失。

最常见的原因是手改随包方块定义时，把行为依赖的某个属性删掉或改名了。把属性补回去就好。

> **不会移除行为的相关警告。** FarmersDelight 也会对配置形态错误发出较温和的警告——比如把一个分组设置写成单个值、
> 某节点下出现未知键、方块列表里写了服务端不认识的标签。这些会被记录，方块仍以默认值继续工作；值得清理，但不是上面那种
> 硬失败。

## 游戏内快速确认清单

- `/ce item give <你> farmersdelight:cooking_pot` 能给出名字和贴图都正确的物品。
- 放在热源上的烹饪锅能打开可用的界面。
- `farmersdelight:cutting_board` 能接受物品，用小刀切一刀能产出结果。
- 控制台有 *Content ready* 行，且**没有** CraftEngine 行为报错。

四条都成立，移植就是加载正确的。
