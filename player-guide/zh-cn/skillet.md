# 煎锅

**煎锅（Skillet）** 一物两用：既是放在热源上的快速煎盘，也是能挥起来砸人的沉重 **近战武器**。

## 合成煎锅

有序合成（工作台）：

```
[      ] [ 铁锭 ] [ 铁锭 ]
[      ] [ 铁锭 ] [ 铁锭 ]
[ 红砖 ] [      ] [      ]
```

- `I` = `minecraft:iron_ingot`（×4）
- `B` = `minecraft:brick`（红砖，×1）

产物：`farmersdelight:skillet` ×1。

## 煎制食物

煎锅煎生食的方式与营火相同 —— 但 **更快**。

1. **放置煎锅**：手持煎锅并 **潜行 + 右键** 目标面，煎锅会朝向你平放。
2. 确保其正下方有 **热源**（点燃的炉灶、点燃的营火、岩浆块、岩浆等 —— 完整列表见炉灶页面）。若煎锅正下方是漏斗，
   则漏斗再下面一格的热源同样能导热上来。
3. **手持带有营火配方的生食右键放置好的煎锅** 即可下锅。再次右键放入同种食物可叠加。
4. 某份煎好后，成品会从锅里 **弹出** 到顶面供你收取。它会逐个煎，直到锅空。

**空手右键** 煎锅可取回锅内食物。若热源熄灭，烹饪进度会回落，直到你重新供热。

**比营火更快：** 煎锅带有烹饪时间缩减，煎食物比在营火上更快。若煎锅物品附有 **火焰附加（Fire Aspect）**，
则更快 —— 每级再削减更多时间（直至一个最短烹饪时间下限）。

## 手持烹饪

一只手拿煎锅，另一只手拿有营火配方的食材，靠近热源后持续按住右键。每次处理一份食材，完成时从另一只手扣除一份，成品进入背包，背包满时掉落。松开右键、切换物品、交换双手、丢弃、操作背包、死亡或退出会中断；未完成食材仍留在原处，进度不保存。

另一只手正在食用或饮用时不会开始烹饪；已有烹饪也会停止推进并中断。食用照常由原版结算，烹饪不会额外扣除这份食材。主副手交换时规则相同。

手持与放置煎锅共用烹饪耗时、倍率和火焰附加加成。默认配置下，600 tick 的营火配方在无附魔煎锅中需要约 120 tick（正常 TPS 下约 6 秒）；放置煎锅按每 4 tick 的检查间隔结算。

耐久条进度和烹饪模型只通过数据包显示给使用者，进度开启时每四 tick 刷新一次；关闭进度后，外观不变时不再周期发包；期间单槽和整包背包同步使用同一份进度显示，真实物品的耐久、模型不变。持续右键不会主动反复挥手。攻击正常消耗真实耐久，物品损坏不会吞掉食材。完成或中断时撤销显示覆盖并刷新真实物品。

1.21.11 及以上的服务端还会在烹饪显示副本上设置 `swing_animation: none`，抑制客户端右键音符盒外观方块时预测的挥手。左键或攻击会中断烹饪并恢复原物品动画；首次按下时，客户端可能已在收到显示副本前挥手一次。旧版客户端没有这个组件，仅取消服务端事件无法消除这类预测动画。

CE 生成资源包时，根据已加载的原版、FD、附属和自定义物品资源生成单层食材贴图叠加，没有固定 16 种食材限制。自动生成支持 `item/generated` 或 `item/handheld` 的单层无染色模型及其父模型继承；多层、染色、条件和特殊 3D 食材使用后备模型，需用 `ingredient-models` 指定外观。这里是静态资源包叠加，不包含原模组的翻锅动画。

服务器可通过 `skillet.handheld.enabled` 关闭手持烹饪，通过 `skillet.handheld.progress-display.enabled` 关闭耐久条进度。手持烹饪关闭后，后续 CE 打包会跳过自动模型生成和缓存目录合并；已有缓存文件保留，已下发的资源包需重新生成、下发才会变化。修改开关后先执行 `/fd reload`；重新启用后重新生成 CE 资源包。模型选项直接写在 CE 物品的 `farmersdelight:skillet_item` 行为下：

```yaml
behavior:
  type: farmersdelight:skillet_item
  permission: farmersdelight.use.skillet
  cooking-model: farmersdelight:skillet_cooking
  ingredient-overlay-model: farmersdelight:item/skillet_food
```

手持烹饪是通用物品行为，上例的模型只属于 FD 煎锅。其他物品可配置自己的模型；不配置模型时保留该物品原外观，烹饪照常。

`cooking-model` 指向 `assets/<命名空间>/items/<路径>.json`，是烹饪基础及后备模型。`ingredient-overlay-model` 指向 `models/` 下的食材叠加模板，模板使用 `#food` 纹理变量，自行定义位置、尺寸和手持变换。`ingredient-models` 仍可按食材 ID 指定完整物品模型，优先于自动生成。移除 `ingredient-overlay-model` 可关闭自动食材外观。

自定义烹饪物品模型可在 JSON 根节点设置 `"hand_animation_on_swap": false`，避免更新进度组件时触发换物品的抬手动画。自动生成的模型及 FD 后备模型已包含此设置。

更新已有服务器时还需同步 CE 包中的行为配置及模板资源，并重新生成、分发资源包；仅替换 FD JAR 不会覆盖已有 CE 配置。自动资源保存在 FD 的 `generated/handheld-cooking` 目录，打包时由 CE 合并。


## 把煎锅当武器

握在手里时，煎锅是一件正经的钝器。其战斗数值：

- **攻击伤害：8**
- **攻击速度：0.9**（缓慢的重挥）
- **击退：+1**（命中时额外推开一段）

伤害与最强的剑相当，代价是挥速慢、且额外击退会把敌人打飞。它既是烹饪工具，也是一件应景又好玩的副武器。

> 煎锅的物品提示会写明它 **可在潜行时放置** —— 这正是你把它放下煎东西、而非挥出去的方式。

## 小贴士

- 在点燃的炉灶上摆一口煎锅，就能在炖锅旁添一个随时可用的快速煎盘。
- 如果你大批量煎食，火焰附加很值 —— 它明显缩短烹饪时间。
- 紧急时无需带剑：手持煎锅一击 8 点伤害，还能把生物击退。
- 由于放置需要潜行右键，你可以直接右键已放置的煎锅来加料，而不会误把它捡起来。
